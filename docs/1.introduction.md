`@antelopejs/checkout-com` implements `@antelopejs/interface-payment` on
Checkout.com's unified Payments API. That is the API generation addressed with a
processing channel (`processing_channel_id`), not the legacy one.

## What maps to what

| Contract                        | Checkout.com                                                             |
| ------------------------------- | ------------------------------------------------------------------------ |
| `CreateCheckoutSession`         | `POST /hosted-payments` (Hosted Payments Page)                           |
| `GetCheckoutSession`            | `GET /hosted-payments/{id}`, then the payment it produced                |
| `CreatePayment`                 | `POST /payments` with a `token` (`tok_…`) or `id` (`src_…`) source       |
| `GetPayment`                    | `GET /payments/{id}`, plus `/actions` for a decline's reason             |
| `CapturePayment`                | `POST /payments/{id}/captures`                                           |
| `CancelPayment`                 | `POST /payments/{id}/voids`                                              |
| `RefundPayment`, `GetRefund`    | `POST /payments/{id}/refunds`. The refund is an action on the payment.   |
| `CreateCustomer`, `GetCustomer` | `POST /customers`, `GET /customers/{id}`                                 |
| `DeleteCustomer`                | `DELETE /customers/{id}`, which also deletes the customer's instruments  |
| `ListPaymentMethods`            | The `instruments` of `GET /customers/{id}`                               |
| `DetachPaymentMethod`           | `GET` then `DELETE /instruments/{id}`, then the customer's record pruned |
| `VerifyWebhook`                 | HMAC-SHA256 `Cko-Signature` from a workflow's webhook action             |

The module declines no function of the contract with `UnsupportedOperationError`.

### Why the hosted page and not a payment link

Checkout.com's Hosted Payments Page and its Payment Links are both hosted pages
for one payment. The Hosted Payments Page is the one Checkout.com positions for a
backend that redirects the payer. It requires success, cancel, and failure URLs
and returns the payer to them. It can save the card for later, which
Checkout.com's comparison marks Payment Links as unable to do. It can also show a
customer's saved cards. Payment Links are for sending a link by email or SMS, and
they leave the payer on a Checkout.com confirmation page.

## Identifiers

Every identifier the contract hands out is Checkout.com's own, except a refund
identifier. Checkout.com keeps a refund as an action on its payment, readable
only through that payment, so a refund identifier is `<pay_…>:<act_…>`. Treat it
as opaque, as the contract asks.

The module reports an identifier that cannot be one of Checkout.com's as not
found, without a call. For example, a payment identifier is `pay_` or `sid_`
followed by 26 characters, a customer identifier is `cus_` followed by 26, and
an instrument identifier is `src_` followed by 26.

## Accounts

The top-level configuration is the default account. `accounts` adds more, keyed
by the name callers pass as the payment interface's trailing `provider`
argument:

```ts fragment
config: {
  secretKey: "sk_…",
  processingChannelId: "pc_…",
  accounts: {
    marketplace: { secretKey: "sk_…", processingChannelId: "pc_…", webhookSignatureKey: "…" },
  },
}
```

A call that names an account the module does not have fails with
`PaymentError`. Each account has its own webhook keys, so `VerifyWebhook` refuses
under one account a delivery signed for another.

## Base URLs and keys

Checkout.com documents a base URL unique to each merchant. The sandbox URL is
`https://{prefix}.api.sandbox.checkout.com` and the production URL is
`https://{prefix}.api.checkout.com`, where the prefix is the first eight
characters of the client ID. Checkout.com says it refuses a request to any other
host with 403 `base_url_invalid`.

Set `baseUrl` from the Dashboard. Without it, the module uses
`https://api.sandbox.checkout.com` for an `sk_sbox_` key and
`https://api.checkout.com` for any other key. If Checkout.com refuses that host,
the `PaymentError` says to set `baseUrl`.

The module sends the key as `Authorization: Bearer <secret key>`.
